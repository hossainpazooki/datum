fact: The vendoring contract in the pack design named `vendor/datum/` as the place a governed repo puts the pack. A Go module cannot use that path for anything: the Go toolchain treats a top-level `vendor/` directory as module vendoring, and with `vendor/` present but no `vendor/modules.txt` every build and vet in the module fails with `inconsistent vendoring`, listing every requirement in `go.mod`. The failure has nothing to do with the pack's contents -- a single unrelated file under `vendor/` is enough. So the contract's load-bearing part is the file set, the pin and the CI order, never the directory name; the first governed Go repo (meridian) places the pack at `gates/datum/`. A conformance contract that hard-codes a path is making a claim about every governed repo's toolchain, which is not a claim it is in a position to make.
